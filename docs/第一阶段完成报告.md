# 在线问卷系统第一阶段完成报告

代码仓库：[GitHub：online-survey-system-phase1](https://github.com/ctasr/online-survey-system-phase1)

## 项目目标

本项目完成了第一阶段的在线问卷系统。用户注册、登录后，可以创建问卷、设置题目和跳转规则，再发布问卷供其他用户填写。创建者可以查看整份问卷和每道题的统计结果。作业要求与代码、测试的对应关系见[第一阶段需求与实现对照](第一阶段需求与实现对照.md)。第二阶段的需求变更尚未发布，本报告只写第一阶段已完成的内容。

代码在`app/`目录，运行入口是`run.py`。依赖和配置方法见`requirements.txt`、`.env.example`和`README.md`。公网演示地址是`https://119.28.27.184/`，问卷分享链接使用同一服务器的`/survey/<slug>`路径。填写者需要登录，问卷也必须处于可填写状态。本地地址`127.0.0.1`只供本机调试，不能发给外部用户。

## 系统设计

后端使用Flask。网页和JSON API共用题目、跳转、校验和统计代码。用户登录后可以创建、编辑和发布问卷。填写者通过分享链接进入问卷，创建者可以查看统计结果和具名答卷。填写页面有题目总览，长问卷可以按题定位，统计页面可以切换到表格。页面提示便于用户改正答案，最终仍由服务器检查。

代码按功能分开。`app/auth.py`处理注册和登录，`app/surveys.py`处理问卷、填写和答卷查看，`app/questions.py`检查题目设置与答案，`app/jumps.py`计算跳转，`app/statistics.py`生成统计结果，`app/api.py`提供JSON接口。网页和API调用相同的校验代码，避免两种填写方式得到不同结果。

问卷先保存为草稿。创建者添加题目和跳转规则，预览后发布。填写者作答并提交，创建者查看统计结果。只有创建者能修改、关闭自己的问卷和查看统计，分享链接不提供管理权限。填写者提交前可以查看题目总览、返回修改并检查漏答。确认提交后，答卷只能查看，不能修改。匿名填写仍需登录，只是提交时不向创建者显示账号。题目很多时，可以使用搜索、分页、总览或表格，不必从头滚到尾。

## MongoDB设计

MongoDB使用`users`、`surveys`、`responses`和`response_drafts`四个集合。题目和跳转规则按顺序保存在问卷文档中，答卷单独保存。用户名、问卷分享标识和受限重复提交都有唯一索引。字段、BSON示例和索引见[MongoDB schema](MongoDB-schema.md)，设计理由见[系统与数据库设计](系统与数据库设计.md)。

| 集合 | 关键字段 | 与其他集合的关系和用途 |
| --- | --- | --- |
| `users` | `_id`、`username`、`password_hash`、`created_at` | 保存账号，只存密码散列，用户名唯一。 |
| `surveys` | `_id`、`owner_id`、`slug`、`status`、`created_at`、`published_at`、`revision`、`questions[]`、`question_history[]` | `owner_id`指向创建者，内嵌有序题目、限制与跳转，公开标识`slug`唯一。 |
| `responses` | `_id`、`survey_id`、`respondent_id`、`answers[]`、`submitted_at`、`viewer_key` | 每次提交独立存储，具名答卷可关联账号，匿名答卷的`respondent_id`为`null`。答案带题目ID和版本。 |
| `response_drafts` | `survey_id`、`user_id`、`answers`、`revision`、`updated_at` | 未提交的临时填写内容，同一账号对同一问卷最多保留一条，不参与统计。 |

题目通常和问卷一起读取，所以保存在问卷文档中。答卷数量会不断增加，单独存放更便于查询和统计。数据库为用户名、问卷分享标识、问卷所有者和答卷所属问卷建立索引。每个账号对同一问卷只保留一份草稿。问卷限制只能填写一次时，数据库索引还会阻止并发重复提交。匿名答卷不保存可供创建者查看的账号ID，填写者仍可通过系统生成的标记找到自己的答卷。

不同题型有不同的设置字段，放在问卷文档中便于保存和读取。答卷会记录提交时的题目版本。题目修改后，系统保留旧版本，查看旧答卷时不会误用新选项。问卷的创建时间与发布时间分别记录。账号、问卷和答卷数据保存在MongoDB中，应用密钥只用于登录会话等安全功能。

## 跳转设计

跳转规则保存目标的题目ID，只允许跳到后面的题目。单选题根据所选项跳转，多选题可以设置“包含任意选项”“包含全部选项”等条件，数字题可以设置数值比较条件。多条规则从上到下检查，使用第一条符合条件的规则。提交时，服务器重新计算实际需要回答的题目。跳过的题目既不用回答，也不会写进答卷。

例如，第1题询问活动类型。选择“户外”时，可以跳过只面向室内活动的第2题，直接进入第3题。选择“室内”时，则继续回答第2题。规则指向固定的题目ID，不依赖会变化的题号。没有符合条件的规则时，系统进入下一题。提交时，服务器根据当前题目和答案重新判断跳转，不能由浏览器自行决定哪些题已跳过。如果问卷在填写期间被修改，旧页面提交会收到版本冲突提示，需要重新核对答案。

## 校验设计

服务器检查必答要求、选择题的选项、多选数量、文本字数、数字范围和整数要求。修改网页输入无法绕过这些检查。问卷修改后，旧页面提交会收到版本冲突提示。已提交的答卷不能修改，关闭或过期的问卷也不能再提交。

题目默认必答，页面只额外标出“选答”。检查只针对实际需要回答的题目。必答题未回答时不能提交，选答题可以留空，因条件跳转而跳过的题目不算漏答。单选题只能选一个已有选项，多选题还要符合最少、最多或固定选项数的设置。文本和数字题分别检查字数、范围及整数要求。页面先提示填写者改正，服务器再检查一次。提交前的确认框会说明答卷提交后不可修改。

统计结果根据已提交的答卷计算。单选题显示各选项的选择人数，多选题显示各选项被选择的次数，文本题显示原文和相同回答的次数。数字题默认显示各答案及人数。平均值等指标仍可查看，测量类题目也可以直接展示这些指标。创建者能查看具名账号的答卷，以及哪些账号选择了某个选项。匿名答卷只参与统计，不显示填写者身份。接口格式和状态码见[API说明](../API.md)。

### 我提出的基础方案

我希望做出一个能实际使用的在线问卷系统。用户注册、登录后，可以创建和管理自己的问卷，不能修改别人的问卷。新问卷先保存为草稿。创建者填写标题和说明，设置是否允许匿名、每个账号可以填写几次、何时截止，然后按顺序添加题目。题目包括单选、多选、文本填空和数字填空，选项和作答限制都由创建者设置，不能只用程序里写死的示例题。

### AI能做什么、没做好什么，我做了什么

AI编写了应用代码、数据库索引、页面、接口、测试脚本和文档，帮助我较快搭起可以运行的系统。但AI起初混淆了题号和选项编号，也没有处理好必答与选答、数学题的统计重点、长问卷查找题目以及具名答卷查看。自动测试通过后，我仍在实际页面上发现问题。因此，AI写出的代码需要按作业要求检查，也需要亲自操作页面验证。

我提出系统目标和使用要求，检查页面并提供截图，指出不方便或不符合要求的地方，再要求AI修改和重新测试。其中，足球问卷应按了解程度分支，数学题应突出答案分布，匿名和具名答卷的查看范围要分清，分享链接要能跨网络打开。这些都是我在实际检查后明确要求修改的。测试步骤与结果见[测试用例与结果](测试用例与结果.md)，接口说明见[API说明](../API.md)。


## 遇到的问题

开发中发现了几类问题。AI曾把题号和选择题的选项编号混在一起，也没有分清必答、选答和条件跳过。长问卷不方便找题，统计页又把与题目无关的数据或不合适的指标放在显眼位置。具名提交后，创建者起初无法查看各账号的答案。本机链接不能供不同网络的人访问，早期测试也缺少截图和实际输入、输出记录。部署期间还出现过公网首页打不开和网页报500错误的情况。当时的完整错误日志没有留存，因此报告不推测那次500错误的具体原因。

## 如何解决

处理这些问题时，我先指出实际页面或操作中的错误，再说明希望达到的效果。AI修改代码后重新运行相关测试，我再查看结果。主要修改如下。

| 问题 | 解决方式 |
| --- | --- |
| AI把A/B/C/D用成题号，必答提示又过于醒目 | 固定题号为数字，字母只用于选择题选项，只强调选答题。 |
| 初版“恰好选择”等文案生硬，取消和返回入口不明显 | 改用日常中文，补表单返回、预览返回与未保存提醒。 |
| 逐题填写时无法一眼看出哪些题已答，必答漏答提示重复题目 | 增加题目总览、按实际跳转路径校验、简短漏答提示和提交前确认。 |
| 长问卷和统计页重复铺满题目，定位与查看都费力 | 增加题目总览、搜索、分页、表格与逐题详情，保留必要的完整题目查看入口。 |
| 统计曾混用“到达”“留空”“跳过”，还加入无关的填写路径分布 | 分开选答未填、有效回答与未包含本题，去掉路径分布。 |
| 具名填写后，创建者只能看到汇总，不能按账号或选项追查 | 增加具名答卷列表、单份完整答卷和单题各答案对应账号，匿名身份不公开。 |
| 按作业要求计算数字平均值，却错误地把数学题平均值作为主要结论 | 默认突出各答案人数，平均值等保留在可展开信息中，测量类题目才直接展示汇总指标。 |
| 本机链接不能跨网络访问，且本地与公网数据库独立 | 将同一应用部署到独立公网服务器，公开链接指向公网地址，区分本地调试与公网演示数据。 |
| 公网根路径一度无法打开，另有页面发生过500错误 | 复查路由与模板，加入中文错误页，用自动测试及公网HTTP检查核对入口。原500的完整异常堆栈未保留，不能声称已查明当时的精确成因。 |
| 起初缺少足够的多账号统计样本与运行证据 | 建立数学和足球两份演示问卷，使用合成答卷核验统计，补真实流程截图、API HTTP测试与具体输入/输出记录。 |

正式提交前仍应打开公网问卷和统计页核对内容，并检查截图与当前版本一致。第二阶段发布新要求后，须在本代码与现有数据的基础上修改，保留第一阶段主要功能，并另写变更、兼容性和新测试报告，不能推倒重做。
