# 第二阶段系统设计与需求变更

## 目标和继承关系

第二阶段在第一阶段 Flask + PyMongo 问卷系统之上增加题目复用、用户间共享、版本历史、题库管理及跨问卷统计。第一阶段的 `users`、`surveys`、`responses`、`response_drafts` 集合、原网页及 `/api/v1` 接口继续使用。代码从第一阶段复制后继续修改，本地另存原提交文件作为对照。两个阶段使用同一GitHub仓库：main固定在第一阶段原提交8745aff，第二阶段从该提交创建phase2分支继续修改。第一阶段文件和原提交时间保留，第二阶段没有另建一套系统。

第一阶段把题目嵌在问卷里，适合按顺序填写和设置本问卷独有的条件跳转，却无法将同一道题独立保存供多份问卷复用。第二阶段没有删除这个结构：独立的题目版本作为可复用来源；选入问卷时，把该版本的定义复制成问卷内题目快照，并保留来源 ID 与版本号。这样第一阶段的作答、跳转、校验和统计仍使用已有结构，版本变化也不能悄悄改变已发布问卷。

## 需求变化与对应实现

| 新要求 | 第二阶段实现 | 对原设计的影响 |
| --- | --- | --- |
| 同一道题用于多份问卷 | `question_library` 保存独立题目；草稿问卷可从题目库选择具体版本 | 问卷仍存题目快照，新增来源 ID、根 ID、版本号，不改变原题目顺序及跳转计算 |
| 分享给其他用户 | 题目所有者可按版本开启或关闭共享，其他登录用户可查看、选用共享版本 | 用户仍只能管理自己的问卷；未共享题目默认返回 404，本人问卷已使用的版本仍可查看详情及统计 |
| 修改不影响已发布问卷 | 题目版本不可原位改写；已发布问卷禁止新增、编辑、删除题目和更改跳转 | 第一阶段曾允许发布后改题，这一行为按第二阶段明确要求改为禁止；既有答卷和统计继续读取 |
| 保存历史、恢复旧版 | 每个题目版本有 `root_id`、递增 `version`、`parent_id`；恢复也是生成新版本 | 历史版本保留，不覆盖旧数据；不同问卷可使用不同版本 |
| 了解使用情况 | 题目详情列出本人问卷及其他用户问卷的稳定匿名编号；从草稿问卷查看题目时可选择只修改本问卷或创建题目新版本；`scope=lineage` 展示各版本概览 | 其他用户问卷名称、内容和管理入口不公开，汇总仍可包含其有效回答 |
| 管理题库 | 用户可创建、改名、删除题库，把版本加入、移除或手动更新到最新可用版本 | 更新题库条目不会自动更新已创建的问卷；删除题库不删除题目或问卷 |
| 跨问卷统计 | 根据题目来源版本检索问卷，再读 `responses` 重算选择次数、填空内容、数字分布与均值 | 统计按准确版本分开；不同版本定义可能不同，不混用选项 |

## MongoDB 设计

原有集合继续保留：

- `users`：用户名、密码散列、注册时间。
- `surveys`：问卷信息、状态、按顺序内嵌的题目及条件跳转；新增题目来源字段 `library_question_id`、`library_root_id`、`library_version`、`library_source_question_version`。第一阶段没有这些字段的旧题目仍可运行。
- `responses`：每次提交独立保存答案和当时的题目版本；跨问卷统计读取实际提交的数据，不把统计结果写死。
- `response_drafts`：未提交的填写进度。

新增集合：

| 集合 | 主要字段 | 原因及索引 |
| --- | --- | --- |
| `question_library` | `_id`、`root_id`、`version`、`parent_id`、`owner_id`、`shared`、题型与校验字段、`created_at` | 一份文档代表一个不可变题目版本。`(root_id, version)` 唯一防止并发创建同一版本；所有者、共享状态供查询。 |
| `question_banks` | `_id`、`owner_id`、`name`、`question_ids[]`、`created_at` | 每个用户自己的题库，引用具体题目版本。`(owner_id, name)` 唯一；可删除组织关系而不删题。 |

既有问卷题目存的是完整定义，不只保存一个外键。这一处冗余是为了固定发布时看到的题目，并沿用第一阶段的填写及跳转逻辑。来源 ID 用于追溯和跨问卷统计；题库文档不复制整道题，只存版本 ID。MongoDB 的文档可自然表达不同题型特有的选项和校验字段，也允许旧文档缺少第二阶段新增字段；不需要为了第二阶段把第一阶段数据迁到关系表中。

## 关键逻辑与兼容性

1. **创建/修改题目。** 新建独立题目产生 v1。修改任一自己拥有的历史版本时，创建新文档，`parent_id` 指向所依据的版本，`version` 在同根题目内递增。恢复旧版内容也创建新文档。共享状态按版本管理，不自动继承。
2. **选入问卷。** 只允许草稿问卷选题。系统复制所选版本的题型、标题、选项和校验规则，同时生成问卷内独立题目 ID。跳转规则仍属于问卷，不复制到题目库。草稿中直接改已选题目时，它与题目库来源脱离，避免把变体误算成原版。
3. **发布后固定。** 发布后的题目、选项、限制和跳转不再修改。问卷标题、说明和填写设置仍按原规则处理。第一阶段形成的 `question_history`、旧答案和旧统计路径保留，不做破坏性迁移。
4. **已有题目入库。** 创建者可将现有问卷题目保存到题目库，增加来源标记，题目内容不变。草稿入库时同时递增问卷 `revision`，防止另一页面保存整份题目列表时覆盖新来源。已发布或已关闭问卷入库不改变 `revision`，已打开的填写页及旧答卷继续对应原题目 ID 和版本。重复操作不重复建题。
5. **统计。** 先找引用准确题目版本的问卷，再按问卷内题目 ID 与答案的题目版本匹配；复用第一阶段统计函数汇总实际提交的答案。不同题目库版本分别统计，避免改过选项后把旧回答归到新选项。等价数字上下限保存不改问卷版本及来源，真正修改边界时才解除来源关联。数字配置、阈值和答案共用范围保护，均值和偶数中位数按所需精度计算。历史异常数字单列invalid_count，不改数据库原文。共享题的跨问卷总数、选项计数和平均值可汇总；逐条填空内容只显示当前用户自己问卷中的记录，按提交时间和答卷ID排序。数字题按该版本设置突出分布或均值概览。
6. **权限。** 所有写入均要求登录和 CSRF。仅所有者能创建新版本、恢复、切换共享；其他人只能新选用仍共享的版本。问卷管理仍按所有者检查。共享题被停止共享后，已在本人问卷中使用该版本的账号仍可查看来源详情及统计，已有问卷快照保持可用，但不能将该版本再次加入新的问卷或题库。所有者仍可选用自己的未共享题目。

本地沿用原来的 `MONGO_DB_NAME` 可直接读取第一阶段数据；没有题目库来源字段的旧问卷无需迁移。若改用新数据库，则需自行迁移旧 MongoDB 数据，复制代码本身不会复制数据库。原有账号、答卷及统计应保留；第二阶段唯一主动收紧的是发布后的题目与跳转编辑权限。

## 保存失败和同时操作的处理

打开页面后，问卷或题库仍可能被其他页面修改。问卷写入使用revision和状态作为条件，题库替换版本时比较原条目列表，改名时比较原名称。条件已变就停止本次操作，不把未成功的写入显示为成功。JSON设置保存同时匹配revision和状态，即使关闭操作没有增加revision，也不能在关闭后误改截止时间。题目已保存、但加入问卷失败时，页面提供已保存题目的入口，避免再次创建。

编辑冲突保留输入和查看最新内容的入口，由用户核对后重试。新建题目版本发生编号冲突时，网页返回409并保留题目及限制设置，直接再次保存即可，不要求刷新页面。题目、跳转和题库改名使用相同原则；发布、关闭和删除还检查最终状态。相同设置重复保存不写入，重复发布和关闭不改时间。缺少revision的旧文档使用兼容默认值，不要求先修改旧数据。

暂存与正式提交分开处理。恢复较慢时只补回未改动的答案；恢复或保存失败时保留当前页面。正式提交等待恢复和排队保存完成，再重新检查问卷状态和答案。关闭、截止或输入错误时不保存正式答卷；提交成功后只清除当前账号在本卷的暂存。

填写页的校验提示只采用当前输入对应的最新请求。输入变化后立即让旧请求失效，较早请求返回的HTTP错误或连接失败不覆盖最新检查结果；当前请求失败仍显示错误并保留输入。服务端校验和正式提交规则不变。

暂存提示也同时核对修改序号和最新保存请求。早一次请求的错误正文延迟返回时，不能盖住后一次成功或失败的提示。最新请求失败仍显示原因，答案留在当前页面，可以继续修改后重试。

## 页面返回和长内容

选题、题库整理、问卷编辑及统计明细之间的返回链接保留原搜索、页码和版本。问卷列表、账号答卷列表及原始回答各用自己的页码参数，避免返回后混淆。长卷加题、删题和调整规则后定位相关题目；长题库更新、移除后定位当前或相邻条目。题目详情中的本人原始填写内容每页20条，翻页后保持展开并定位该区域，保留题库、搜索和原页码。JSON统计接口的完整values列表不受网页分页影响。

跳转设置中的目标题目搜索按回车只执行查找，不提交规则；规则有未保存的变更时，误点其他页面会提示离开。明确点击取消则直接返回原题，正常保存不受影响。

答卷可以显示完整题目和全部选项，翻页后保留显示方式。题号固定使用数字，选项可使用数字或字母编号。从问卷进入库题详情、新版本编辑及预览时保留来源问卷的选项编号，校验失败返回后也不改变。独立题目库默认使用数字编号。统计表的已回答列统一显示份数，选答未填单独列出，避免把未解释的分母当作总答卷数。包含已移除题目的旧答卷按原问卷顺序编号，答案不改写。相同时间的列表按ID再排序，网页与API保持相同顺序。第一阶段遗留题目较新版本无回答且已移除时，单题统计默认打开有回答的最近历史版本，账号入口和原文分页均携带实际版本，未知版本返回404。

长文本统计使用原文SHA-256摘要作为筛选标识，不把整段答案放进URL。服务器只在当前账号有权查看的问卷、题目版本和答案中查找；匿名答卷计入汇总，不进入账号明细。手机页面逐条显示账号、时间和详情，减少横向滚动。

## API、分享和演示数据

API检查JSON对象、答案类型、登录和CSRF，错误请求不修改数据库。网页错误使用中文页面，API错误保持JSON和原状态码。具体路径、字段及错误示例见[API说明](../API.md)。

分享链接从PUBLIC_BASE_URL生成。未配置公网地址时只提供本机入口，不把127.0.0.1当作别人可以访问的地址。剪贴板受限时显示可手动复制的完整链接。

测试夹具tests/campus_fixtures.py通过原API构造图书馆、食堂和创客空间示例，不新增业务集合。模拟文档带demo_seed_suite、demo_key、demo_generated_at和demo_timeline_simulated标记，区分模拟时间与实际生成时间；不修改原有问卷内容、答卷和密码。

系统代码、API说明、测试记录和完成报告按同一版本整理，Prompt日志与AI使用说明放在完成报告中。第一阶段提交目录保留原样，第二阶段没有改成另一套系统。报告中的问题及解决办法与实际修改对应，后台浏览器操作不记为人工测试。
