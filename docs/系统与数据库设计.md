# 第一阶段系统与数据库设计

## 需求边界与结构

系统按原作业的第一阶段初始需求实现：注册与登录、本人问卷管理、四类题目、可配置的条件跳转、登录后填写与校验、匿名或具名提交、整卷及单题统计。网页和 `/api/v1` JSON API 共用 Flask 业务代码与 MongoDB。第二阶段的需求变更尚未提供，因此目前不把自行设想的新功能写成第二阶段要求。

请求经 `app/auth.py` 鉴别身份；`app/surveys.py` 负责网页和问卷流程；`app/questions.py` 对题目与答案作服务器端校验；`app/jumps.py` 计算下一题；`app/statistics.py` 读取答卷生成统计；`app/api.py` 提供 JSON 接口。题目和跳转规则存在问卷数据里，不能靠题号写死在程序里。

## MongoDB 集合

| 集合 | 主要字段 | 关系与用途 |
| --- | --- | --- |
| `users` | `_id`、`username`、`password_hash`、`created_at` | 账号；只存密码散列。`username` 唯一。 |
| `surveys` | `_id`、`owner_id`、`slug`、`title`、`description`、`status`、`published_at`、`deadline`、`revision`、`questions[]`、`question_history[]` | 一份问卷及其按序排列的题目、限制和跳转规则。`slug` 唯一，`owner_id` 指向创建者。 |
| `responses` | `_id`、`survey_id`、`survey_title`、`respondent_id` 或匿名标记、`answers[]`、`submitted_at`、`respondent_key` | 一次提交一份文档；每项答案带 `question_id`、`question_version`、`value`。同一账号可有多份答卷，取决于问卷设置。 |
| `response_drafts` | `survey_id`、`user_id`、`answers`、`revision`、`identity_mode` | 未提交的临时填写内容；同一账号对一份问卷最多保留一条。 |

问卷拥有一组通常一起读取、规模受问卷本身控制的题目，所以题目嵌在 `surveys` 文档中并保持顺序。答卷可以不断增长，必须独立于问卷存入 `responses`；否则单份问卷文档会持续膨胀，统计、分页和并发提交也会不便。账号独立存储，以 `ObjectId` 关联；不使用关系数据库的表与外键，因为作业规定 MongoDB，且问卷题目的类型与校验字段并不固定，文档结构适合表达这些差异。不是把所有数据塞进一个集合。

问卷创建时写 `created_at`，发布时才写 `published_at`，关闭时写 `closed_at`；三者不互相替代。时间存 UTC，页面按北京时间展示。题目定义变化后将旧定义写入 `question_history`，答卷保存题目版本；旧回答仍按原选项解释。已提交答卷不可修改。调整数字题的统计展示方式不改变题目版本和已有答卷。

## 索引与边界

启动时 `app/db.py` 建立用户名和公开标识唯一索引、问卷所有者索引、答卷所属问卷索引、答卷个人查询索引、草稿 `(survey_id,user_id)` 唯一索引，以及限制一次填写时的 `(survey_id,respondent_key)` 局部唯一索引。最后一项防止并发提交绕过只填一次的检查。匿名答卷不保存明文答题者账号 ID；本人仍能用单向派生的查看标记找回自己的答卷。

网页修改操作须验证 CSRF；API 的写操作同样检查会话令牌和 JSON 格式。创建者查询始终以 `owner_id` 过滤，他人不能查看或修改该问卷及其统计。公开填写链接可以跨网络访问部署在公网的服务，但填写者仍须登录；`127.0.0.1` 仅表示访问者自己的电脑，不能作为分享链接。

## 跳转、校验与统计

题目按数组顺序呈现。每条跳转规则含目标题 ID 和条件：单选按选项、多选按集合关系、数字按比较运算；只允许跳向后续题目，多条规则按顺序命中第一条有效规则。未命中则进入下一题。服务器在提交时沿同一路径重新计算，跳过的题目无需回答，也不写入答卷。浏览器端预览和总览用于提高可用性，不能替代服务器校验。

单选值须来自选项；多选须满足最少、最多或固定项数；文本按字数；数字按上下限和整数要求检查。必答题在实际经过的路径上不可留空。每个统计结果区分“已回答”“选答未填”“跳过或当时不存在”。单选展示各项人数，多选展示各项被选次数，文本展示原文及频次。数字题默认以各答案人数为主；平均值、中位数与范围仍可在次级信息中查看，以满足原作业“可以查看平均值”的要求。创建者明确选择“数值测量”时，这些汇总指标才直接展示。统计每次从已保存答卷重算，不缓存写死的结果。

## 运行配置

依赖和启动命令见根目录 `README.md`，完整接口见 `API.md`。本地数据库使用 `MONGO_URI` 和 `MONGO_DB_NAME`；固定分享地址使用 `PUBLIC_BASE_URL`；会话签名使用稳定的 `SECRET_KEY`。正式部署和本地调试各有独立数据库，不能把本地 `127.0.0.1` 链接当成公网链接，也不能假定两个环境的演示数据自动同步。不要把 `.env`、密钥、数据库备份或测试账号密码提交到公开仓库。
